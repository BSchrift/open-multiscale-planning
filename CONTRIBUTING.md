# Contributing

Thanks for helping. Open an issue before starting anything large, so we can agree on the approach first.

## Making a change

- Run the app and tests locally as the [README](README.md) describes. `make test` runs the full local suite and needs only Docker.
- Write the failing test first, then the smallest change that makes it pass.
- Never commit secrets, real names or emails, or personal data. Your own settings go in the gitignored files next to each `.example`.
- A pull request needs CI to pass.

## Contributor License Agreement

Before your first pull request can be merged, you need to sign the [Contributor License Agreement](CLA.md). You keep the copyright in your work. The agreement lets the maintainer license the project, including your contributions, under terms other than the AGPL, and promises your contributions also stay available under an open source license.

When you open your first pull request, a bot asks you to sign. Read [CLA.md](CLA.md), then comment on the pull request with exactly:

```
I have read the CLA Document and I hereby sign the CLA
```

One signature covers all your future contributions. If you contribute as part of your job, check first that your employer allows it (section 4).
